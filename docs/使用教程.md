# NXCRM 使用教程

本教程依据当前仓库的菜单、路由、表单和业务代码编写。界面可用操作受账号权限和自定义字段配置影响；菜单名称可能随语言或管理员设置变化，可用下表中的路径定位页面。默认后台前缀为 `/admin`。

## 首次登录与基础配置

### 1. 登录并修改密码

访问 `/admin`。全新 CLI 安装的管理员账号为 `admin/admin`。登录后通过个人设置 `/admin/auth/setting` 修改密码；管理员也可以进入用户管理编辑对应账号。

初始化迁移还会插入 `niutiezhu` 示例账号，上线前在用户管理中核查，按实际需要删除或修改其密码及权限。

### 2. 设置站点和公司资料

打开 `/admin/settings/setting`：填写网站名称、网站地址、LOGO、菜单位置和登录页样式。**后台的“网站地址”按表单要求以 `/` 结尾**，例如 `http://127.0.0.1:8000/`。`.env` 的 `APP_URL` 示例则为 `http://127.0.0.1:8000`。

打开 `/admin/settings/company`：填写公司全称、简称、电话、邮箱和地址。这些信息用于生成 Word 合同中的乙方内容。

### 3. 建立团队和权限

1. 在 `/admin/auth/roles` 建立角色 / 部门，配置上级部门、负责人、权限和菜单。
2. 在 `/admin/auth/users` 新建员工，填写用户名、姓名、手机号、密码和所属角色。
3. 使用员工账号重新登录，检查能看到哪些菜单、能读取哪些客户、能否执行预期操作。
4. 按业务需要调整权限；员工使用独立账号，便于记录负责人及操作归属。

菜单权限与业务数据可见范围需要分别验证。不要只凭管理员账号看得到页面，就认定员工权限配置已经完成。

## 线索、客户与跟进

### 建立线索

在“线索”列表新增记录，填写名称及已启用的业务字段。新增记录归属当前登录用户。建议先查询名称，避免重复录入。

线索行操作包括“转为客户”“放入公海”；公海记录可显示“领取线索”。确认真实业务归属后再操作。

### 转为客户或直接新建客户

在线索列表选择“转为客户”，确认后该记录变为正式客户，可在客户列表查询。这个操作改变记录状态；不会自动生成商机、合同或收款。

已确定合作关系的客户，也可以直接在客户列表新增。打开客户详情查看联系人、跟进、合同、收款、发票、订单及附件等关联信息。

### 联系人与跟进

从客户详情的联系人区域新建联系人，填写姓名、手机号及自定义字段，确保关联到正确客户。建议从详情页进入新增操作，避免手工录入错误的业务 ID。

每次沟通后在对应详情页记录跟进内容，例如需求、报价反馈、下一次沟通安排。跟进记录是公海回收判断的依据，业务沟通完成后应及时录入。

### 协作与附件

客户详情提供共享及负责人调整入口时，选择目标员工并确认。操作后检查双方账号的可见范围。具体入口是否可用由权限和页面状态决定。

从客户、合同或其他业务详情上传附件，以便自动关联对应记录。支持的普通附件包括图片、ZIP、Word、Excel、PPTX、TXT、PSD、PDF 等；电子档图片表单支持 JPG / PNG / GIF / JPEG，最多 10 张。

当前默认上传磁盘为 `public`，文件可通过 `/storage/...` 访问。涉及敏感合同资料时，应先评估公开文件链接是否符合团队需求；账号登录权限不会自动保护这个公开存储地址。

## 商机、产品与合同

### 管理商机

新增商机时填写主题、所属客户、预计收入、预计结束日期、进度和备注。当前进度选项为：前期接触、机会评估、需求分析、方案提供、多方选择 / 评估。

根据沟通结果及时更新进度或使用列表提供的状态操作。商机金额代表预计收入，实际合同和收款需要分别录入。

### 建立产品

在产品列表新增名称、单位、成本、销售价格和上线状态。创建合同前先维护好产品，便于选择合同订单中的产品。

### 创建合同

1. 选择所属客户。
2. 填写签署时间、到期时间，选择状态：未开始、执行中、正常结束、意外终止。
3. 在“合同订单”中添加产品、成交单价和数量。
4. 填写备注、自定义字段和履约步骤。履约步骤可包含时间节点、履约内容和收款金额。
5. 保存后核对合同总额、产品订单和所属客户。

当前代码在新增合同时按订单的成交单价 × 数量累计总额，并保存产品标准价快照。修改已有订单后应检查合同总额是否正确；本教程不假定编辑时一定重新计算。

“订单”页面用于查询合同产品明细，当前界面关闭独立新增和行操作。需要维护订单时从合同表单进入。

## 收款、支出与发票

### 登记收款和支出

在收款页面新增，填写金额、方式、所属合同、备注和时间。支出通过支出页面登记，保存后在合同详情核对统计。

选择需要开票时，可在收款表单中填写开票金额、类型、抬头和邮寄信息。金额、合同归属与实际到账时间应以真实凭证为准。

### 管理发票

在发票页面创建或查看记录，填写所属合同、金额、类型、企业或个人抬头。企业抬头按需填写税号、开户行、账号及开票地址，邮寄资料填写联系人和地址。

通过界面提供的状态操作记录办理进展。这里管理的是发票业务信息，不代表已经与税务开票平台对接；实际开票后再更新状态并上传凭证。

## 导入与导出

### 导入线索 / 客户

1. 准备 `.xlsx` 或 `.csv` 文件。当前上传界面接受这两种格式，先用少量数据测试。
2. 首行建议作为标题行；当前表单可指定标题行号，但字段映射页面对非首行标题的适用情况应另行验证。
3. 打开 `/admin/import/form`，选择线索或客户，设置标题行并上传文件。
4. 在“对应关系”中，将系统字段与表格列逐一匹配，包括启用的自定义字段。
5. 提交后到对应列表核查数量、名称、字段内容和负责人。

示例：系统至少提供“客户名称”映射；如果已启用“行业”“来源”等自定义字段，可以增加相应表格列。

| 客户名称 | 行业 | 来源 |
| --- | --- | --- |
| 示例客户 A | 制造业 | 展会 |
| 示例客户 B | 软件服务 | 网站咨询 |

当前导入入口仅开放线索、客户；不要按界面未提供的类型导入合同或联系人。所有需要的字段均应匹配有效列，避免空映射导致导入失败。

当前任务采用批量插入，没有启用“覆盖 / 跳过重复记录”策略。重复提交可能产生重复数据，不能依赖表单字段的唯一性校验自动去重。批量操作前先备份，统一清理文件中的重复名称和无效数据。

默认 `QUEUE_CONNECTION=sync` 时，任务随请求执行。数据量大时可能超时或占用较多内存，先分批导入；异步配置见维护教程。

### 导出

在提供导出按钮的列表中，按业务需要筛选并使用界面提供的导出范围。导出后检查行数和字段，包含客户资料的文件应按团队要求保存和分享。不同列表是否开放导出，以实际界面为准。

## 合同范本与生成

1. 先保存公司资料，并建立包含客户和产品订单的合同。
2. 制作 Word `.docx` 范本，将需要替换的位置写为占位符，例如 `${甲方}`。
3. 在“合同范本”新增名称、说明和 `.docx` 文件。
4. 打开“生成合同”，选择业务合同和范本，提交后使用完成页的下载入口。
5. 打开下载文件，检查双方资料、日期和金额后再使用。

当前支持的变量：

| 占位符 | 数据来源 |
| --- | --- |
| `${甲方}` | 客户名称 |
| `${乙方}`、`${乙方简称}` | 后台公司名称及简称 |
| `${乙方电话}`、`${乙方邮箱}`、`${乙方地址}` | 后台公司资料 |
| `${乙方经办}` | 当前登录员工姓名 |
| `${合同开始}`、`${合同截止}` | 合同签署日期、到期日期 |
| `${当前日期}` | 生成当天的日期 |
| `${合同总额小写}`、`${合同总额大写}` | 根据合同产品订单计算的金额 |

当前代码写入固定文件 `storage/app/public/files/modelcontract.docx`，下一次生成会覆盖它。因此生成后及时下载归档；多人同时生成时应先解决文件命名冲突，不能将这个固定地址当作历史合同档案。

## 公海与消息提醒

### 公海回收与领取

在 `/admin/settings/highseas` 配置过期天数：线索默认 30 天，客户默认 180 天。自动回收同时检查记录创建时间和最近期限内是否存在跟进记录；符合条件时清除原负责人，放入公海。

人工可在线索 / 客户列表使用“放入公海”或领取操作，入口取决于当前记录状态及权限。定期检查公海中的记录，领取后安排跟进。

自动回收需要系统定时任务运行，只启动网页服务不会自动执行，配置方式见[定时任务](部署与维护.md#定时任务)。

### 合同到期通知

打开 `/admin/settings/reminder`，选择提前通知时间，并分别设置客户、销售人员的通知方式。客户通知支持短信；销售通知支持短信和站内提醒。未接入短信服务时，可以先选择销售人员的站内提醒，并将客户通知留空。

**全新安装后必须保存一次这个表单，再启用调度。** 代码直接读取保存后的 `contract_day`，未配置时调度会报错。

表单中的“一周 / 一月”在当前实现中同时控制通知时间范围和执行周期：`weekly` 筛选未来 7 天到期合同并按周调度；`monthly` 筛选未来 31 天并按月调度。若需要每日检查到期合同，应另行修改调度并验证业务规则。

短信需在站点设置的短信配置中填入真实阿里云账号、短信签名，并在提醒设置中填入匹配的模板 CODE。发送前检查联系人 / 销售手机号及模板参数。配置 `.env` 的 SMTP 并不会自动启用合同短信提醒。

## 自定义字段与业绩目标

### 自定义字段

在 `/admin/customfields` 选择客户、联系人或合同，设置中文名称、英文标识、字段类型、是否必填、列表显示、默认值、提示和排序。

英文标识需要以字母开头，仅包含字母、数字或下划线，长度至少 3。先用一条测试记录验证录入和显示，再应用到真实数据。字段修改前检查历史记录及导入映射，避免改变原字段含义。

### 业绩目标

在 `/admin/programs` 设置新增客户数、商机数及金额、合同数及金额、收款金额等目标。当前表单将目标关联到当前登录用户；使用员工账号维护后，结合首页实际提供的统计查看进展。

## 完整业务练习

建议在测试环境按顺序完成一次：

1. 管理员建立“销售”部门和测试员工，验证员工登录及菜单权限。
2. 员工新增“示例客户 A”线索，并添加联系人和一条跟进。
3. 通过线索行操作转为客户，确认客户详情中的关联信息。
4. 新建商机，填写预计收入和结束日期，更新一次进度。
5. 新建产品“服务包”，单位“套”，销售价格 1,000 元。
6. 创建合同，选择该客户，添加服务包，成交单价 1,000 元、数量 2，核对新增合同金额为 2,000 元。
7. 登记一笔 1,000 元收款，核对合同详情中的收款记录；按需登记发票信息。
8. 从合同详情上传测试附件，用 Word 范本生成合同并检查金额和公司资料。
9. 使用另一员工账号核查共享、权限及公海领取结果。

完成后核查各模块关联和金额，并清理测试记录。这是业务验收步骤；当前安装验证仅覆盖环境、登录、首页和静态资源。
