本文适用于本仓库的 Laravel 10 版本。命令默认在项目根目录执行；macOS / Linux 使用终端，Windows 建议在 WSL 中执行通用安装流程。

## 环境准备

| 软件 | 本项目要求与说明 |
| --- | --- |
| PHP | `composer.json` 要求 `^8.1.0`；本次使用 PHP 8.2.34 验证通过，其他版本以锁定依赖的检查结果为准 |
| Composer | 使用 Composer 2，按 `composer.lock` 安装依赖 |
| MySQL | 本仓库按 MySQL 8.0 使用；本次验证版本为 8.0.45 |
| Node.js / npm | 仅修改或重新编译前端资源时需要，普通启动可使用仓库内的 `public` 静态资源 |
| Redis | 默认文件缓存、文件会话和同步队列不依赖 Redis；启用 Redis 队列 / Horizon 时另行配置 |
| Web 服务 | 本地使用 `artisan serve`；服务器使用 Nginx + PHP-FPM |

PHP 应具备 `ctype`、`curl`、`dom`、`fileinfo`、`filter`、`hash`、`mbstring`、`openssl`、`pcre`、`pdo`、`pdo_mysql`、`session`、`tokenizer`、`xml`，以及导入导出需要的 `zip`、`xmlreader`、`xmlwriter`；本项目还应启用 `bcmath`、`gd`。Horizon 使用 `pcntl`、`posix`，因此异步任务环境使用 macOS / Linux / WSL。

检查已安装的软件：

```bash
php -v
php -m
composer --version
mysql --version
```

通过操作系统的软件管理器或软件官方安装包准备上述环境。CLI PHP 与 PHP-FPM 应使用兼容的版本及扩展。Laravel 10 的基础要求可核对[官方部署文档](https://laravel.com/docs/10.x/deployment)。

## 全新安装

### 1. 准备项目和配置文件

将仓库克隆或解压到本地，然后进入项目根目录。根目录中应有 `artisan`、`composer.json`、`composer.lock` 和 `.env.example`。

仅在没有 `.env` 时复制模板，避免覆盖已有配置：

```bash
test -f .env || cp .env.example .env
chmod 600 .env
```

使用编辑器打开 `.env`，将以下配置合并到文件中，其余项目按需保留：

```dotenv
APP_NAME=NXCRM
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://127.0.0.1:8000
ADMIN_HTTPS=false

LOG_CHANNEL=stack

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=nxcrm_local
DB_USERNAME=nxcrm
DB_PASSWORD="替换为你设置的数据库密码"

BROADCAST_DRIVER=log
CACHE_DRIVER=file
QUEUE_CONNECTION=sync
SESSION_DRIVER=file
SESSION_LIFETIME=120
MAIL_MAILER=log
```

`APP_KEY` 将由首次安装命令生成。模板中的密钥、数据库密码和演示站点地址应替换；不要把当前电脑的随机密码复制到教程或版本库。数据库密码含空格或 `#` 时必须加引号。

### 2. 创建数据库与专用账号

先启动你安装的 MySQL 服务，再用具备建库和建用户权限的账号连接：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p
```

在 MySQL 提示符下执行以下 SQL，替换示例密码：

```sql
CREATE DATABASE nxcrm_local
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'nxcrm'@'127.0.0.1'
  IDENTIFIED BY '替换为你设置的数据库密码';
GRANT ALL PRIVILEGES ON nxcrm_local.* TO 'nxcrm'@'127.0.0.1';
EXIT;
```

如果数据库或账号已存在，先确认其用途及授权，不要删除重建。这里的数据库名、账号、密码和端口必须与 `.env` 一致。账号授权绑定的来源地址也必须匹配实际连接方式。

测试应用账号连接：

```bash
mysql -h 127.0.0.1 -P 3306 -u nxcrm -p nxcrm_local
```

能够进入 MySQL 提示符后，执行 `EXIT;` 返回终端。

### 3. 安装 PHP 依赖

```bash
composer install --no-interaction --prefer-dist
composer check-platform-reqs
```

检查结果应通过。缺少扩展时，先为当前 PHP 安装或开启对应扩展，再重试。常规安装使用 `install` 保持锁定版本；`update` 会重新解析依赖，属于升级操作。详见 [Composer 官方说明](https://getcomposer.org/doc/01-basic-usage.md)。

### 4. 初始化全新数据库

确保 `storage`、`bootstrap/cache` 可由运行 PHP 的用户写入，然后执行：

```bash
php artisan nxos:install --no-interaction
```

命令会清理缓存、建立上传目录链接、生成应用密钥、执行数据库迁移、导入初始配置、将管理员重置为 `admin/admin`，最后清理视图缓存。

**此命令只用于首次安装空数据库。** 重复运行会重新生成 `APP_KEY`、重置管理员密码，并清空重建菜单、权限、扩展及扩展历史表。已有数据的环境按[升级流程](部署与维护.md#升级流程)操作。

当前仓库包含旧的 `public/install.php`，其页面仍显示其他产品名称及旧 PHP 要求。本教程使用已经验证的 CLI 安装命令。上线时按部署教程禁止访问该文件。

### 5. 启动应用

```bash
php artisan serve --host=127.0.0.1 --port=8000
```

保持此终端运行，浏览器打开：

- 后台：<http://127.0.0.1:8000/admin>
- 登录页：<http://127.0.0.1:8000/admin/auth/login>
- 初始用户名：`admin`
- 初始密码：`admin`

在运行服务的终端按 `Ctrl+C` 可停止服务。MySQL 需要同时保持运行。更换端口时同步修改 `.env` 的 `APP_URL`，再执行 `php artisan optimize:clear`。

### 6. 可选：编译前端资源

仓库已经包含后台和业务页面所需静态资源，首次启动通常不需要 npm。修改 `resources/js` 或 `resources/sass` 后，才执行：

```bash
npm ci
npm run development
```

发布构建使用 `npm run production`。该项目使用 Laravel Mix 5 / Webpack，脚本不是 Vite；Node 版本兼容性需要在构建环境验证。不要混用 npm 和 Yarn 更新锁文件。

## 环境变量说明

| 配置 | 用途 / 修改时机 |
| --- | --- |
| `APP_ENV` | 本地 `local`；服务器 `production` |
| `APP_DEBUG` | 本地排查问题可设 `true`；对外服务设 `false` |
| `APP_KEY` | 加密密钥；首次生成，后续升级、备份恢复必须保留 |
| `APP_URL` | 实际访问地址，含协议和端口；影响上传文件地址 |
| `ADMIN_HTTPS` | HTTPS 后台设 `true`；本地 HTTP 设 `false` |
| `ADMIN_ROUTE_PREFIX` | 可选，默认 `admin`；修改后同步检查根路径跳转和菜单链接 |
| `DB_*` | 数据库连接参数；本机独立实例使用 `3307`，通用示例使用 `3306` |
| `CACHE_DRIVER` | 默认 `file`，本地无需 Redis |
| `QUEUE_CONNECTION` | 默认 `sync`，导入任务在请求中执行；异步方案见维护教程 |
| `SESSION_DRIVER` | 默认 `file`，要求 `storage/framework/sessions` 可写 |
| `MAIL_MAILER` | 本地设 `log`，不发送真实邮件；需要邮件时填真实 SMTP 配置 |
| `REDIS_CLIENT` | 使用仓库内 Predis 时设置 `predis`；否则默认配置使用 PHP Redis 扩展 |

修改 `.env` 后执行：

```bash
php artisan optimize:clear
```

运行中的服务和队列进程应重启以加载新配置。站点名称、公司资料、公海规则和短信设置还需要在后台配置，详见使用教程。

### 检查是否已经运行

```bash
cd /Users/jingxuehui/Desktop/demoSpace/nxcrm
lsof -nP -iTCP:3307 -iTCP:8000 -sTCP:LISTEN
curl -I http://127.0.0.1:8000/admin/auth/login
```

如果两个端口都在监听且登录页可访问，直接使用即可。端口被其他进程占用时，先查看进程归属。

### 重启本地 MySQL

仅在独立实例没有运行时执行：

```bash
cd /Users/jingxuehui/Desktop/demoSpace/nxcrm
/usr/local/mysql/bin/mysqld --no-defaults \
  --basedir=/usr/local/mysql \
  --datadir="$PWD/storage/app/mysql-local" \
  --bind-address=127.0.0.1 --port=3307 \
  --socket="$PWD/storage/app/mysql-local/mysql.sock" \
  --pid-file="$PWD/storage/app/mysql-local/mysql.pid" \
  --log-error="$PWD/storage/app/mysql-local/mysql.log" \
  --mysqlx=OFF --daemonize
```

此实例不是通过 Homebrew 管理的服务。不要使用 `brew services restart mysql` 代替上述命令，也不要在运行中删除数据目录。

### 重启本地 Web 服务

8000 端口空闲时，在项目根目录启动：

```bash
/opt/homebrew/opt/php@8.2/bin/php artisan serve \
  --host=127.0.0.1 --port=8000
```

这次手动启动是前台运行，按 `Ctrl+C` 停止；旧的 `local-server.pid` 只记录之前的后台进程，不会自动更新。

### 停止之前后台启动的服务

先查看 PID 和进程命令，确认它们属于本项目：

```bash
cat storage/app/local-server.pid
cat storage/app/mysql-local/mysql.pid
ps -p "$(cat storage/app/local-server.pid)" -o pid,command
ps -p "$(cat storage/app/mysql-local/mysql.pid)" -o pid,command
```

确认后停止，先 Web 后数据库：

```bash
kill -TERM "$(cat storage/app/local-server.pid)"
kill -TERM "$(cat storage/app/mysql-local/mysql.pid)"
```

若 PID 文件不存在或进程已经退出，使用 `lsof` 重新查找，不要根据过期 PID 杀进程。停止 Web 后再次检查 8000 端口，确认 PHP 子进程也已退出。

## 常见问题

| 现象 | 排查与处理 |
| --- | --- |
| 找不到 `vendor/autoload.php` | 在根目录执行 `composer install` |
| Composer 提示 PHP / 扩展不兼容 | 检查 `php -v`、`php --ini`、`php -m`；修复环境后运行 `composer check-platform-reqs`，不要跳过平台校验 |
| `Connection refused` | 检查 MySQL 是否启动以及 `DB_HOST` / `DB_PORT`；当前电脑使用 `3307` |
| `Access denied` | 核对账号、密码及 MySQL 用户来源地址；用相同连接参数手动登录 |
| `Unknown database` | 创建 `.env` 中指定的数据库，或改为正确的数据库名 |
| `could not find driver` | 为实际运行的 PHP 开启 `pdo_mysql` |
| `No application encryption key` | 仅全新环境生成密钥；已有系统从备份恢复原 `APP_KEY` |
| 500 / 日志或视图目录不可写 | 查看 `storage/logs/laravel.log`，修复 `storage` 和 `bootstrap/cache` 的运行用户权限 |
| 419 / 登录失效 | 统一使用 `.env` 配置的域名、协议；检查会话目录可写，清理缓存并清除浏览器旧 Cookie |
| 上传文件 404 / 地址不正确 | 检查 `APP_URL`，执行 `php artisan storage:link`，确认 Web 服务能读取 `storage/app/public` |
| 端口 8000 被占用 | 查看 `lsof -nP -iTCP:8000 -sTCP:LISTEN`；换端口时同步改 `APP_URL` |
| 修改 `.env` 不生效 | 执行 `php artisan optimize:clear`，重启服务及队列进程 |
| 定时任务报 `Undefined array key "contract_day"` | 先在 `/admin/settings/reminder` 保存消息通知设置，再执行 `php artisan schedule:list` |
| 忘记管理员密码 | 具有服务器权限时运行 `php artisan nxos:reset`，会变成 `admin/admin`，登录后立即改密码 |

排查时先保留错误原文和日志，再处理具体原因；不要通过重复安装或清空数据库处理启动错误。
